# 抽卡报表规则（规范）

这个文件是**报表口径与呈现的规范**，回答两个问题：**为什么这样算**、**为什么这样画**。
它不随实现变化——代码可以重写、模板可以替换，这里定义的规则是要长期守住的。

## 谁该读这个文件

| 读者 | 用法 |
|---|---|
| **用户 / Agent 日常出报表** | **不用读这个文件**。直接 `node scripts/build-report.mjs`，模板已经实现全部规则 |
| **开发 / 修改这个 skill** | **必须读**。改口径、改配色、改版式前先看这里，改完回来同步 |
| **接手维护的人** | 先读这里，再看 `scripts/build-report.mjs` 与 `assets/report/` 的实现 |

**规则与实现的分工：**

| 层 | 位置 | 角色 |
|---|---|---|
| 规则（本文件） | `references/report-rules.md` | 规范。定义口径、配色语义、版式要求、踩过的坑 |
| 配置 | `config/report.json` | 可调参数：称号分档、标签阈值、配色值、文案、频道定义 |
| 实现 | `scripts/build-report.mjs` + `assets/report/` | 默认模板。把规则落成可运行代码 |

**优先用模板，不要重新发明**：`scripts/build-report.mjs` 已经实现了下面的全部规则。
只有在模板确实不适用、或你要做定制版式时，才需要按本文件手写实现。

## 0. 怎么出报表

```bash
node scripts/build-report.mjs          # data/ → output/report.html
```

产物：单文件 `output/report.html`，内联数据、ECharts 与用到的图标（base64），可单独发送。
ECharts 5.6.0 已 vendored 在 `assets/vendor/echarts.min.js`（校验见 §7），报表不联网、不用 CDN。

## 1. 口径

- **UP 轮**：从上一个 UP 结束后开始。`off` = 期间所有非 UP 金的抽数，`up` = UP 金自己的抽数，`total = off + up`。
- **十连副金并回本轮**：同一发十连里排在 UP **之后**的非 UP 金（`record_time` 同秒且 `sort` 差 ≤ 9），把它的 `count` 并入这一轮的总抽，本轮仍算**直出**。不留给下一个 UP——否则下一位会被误判成「先歪」。
- **保底获得（guar）**：上一轮末尾带出了十连副金，说明 50/50 已经歪过，这一发是大保底。它**不计入 50/50 胜场**，并且**打断连 UP**。
- **指标**（每金 / 每 UP 一律用「官方总抽 − 当前垫抽」）：
  - 每 UP 均 = (角色池总抽 − 角色池垫抽) / UP 轮数
  - 不歪率 = 胜场 / UP 轮数（胜场 = 直出且非保底获得）
  - 平均每金 = (该频道总抽 − 该频道垫抽) / S 数
  - **为什么扣垫抽**：`type_stats[].total_count` 含「已经抽掉、但还没出 S」的垫抽。
    把它摊进每个金，等于把一个尚未结算的成本算进历史均值。官方自己的 `avr_up_count`
    就是扣掉垫抽的：常驻 650/9 = 72.2，官方 65.8 = (650−58)/9；复刻角色 90/1 = 90，官方 76 = (90−14)/1。
    示例账号的角色池垫抽恰好是 0，所以旧口径没露馅——换个号就会系统性偏非，**称号也会跟着偏**。
  - 报表构建时会拿扣垫抽后的每金和官方 `avr_up_count` 交叉核对，差超 0.1 就告警。
- **欧判定**：`total ≤ 该账号的每 UP 均` 即算欧（歪了但更省也算）。**不要写死 87.9**，那是示例账号的值。
- **极欧**：`total ≤ 40`（`config.report.json` 的 `numbers.extremePulls`）。

### 1.1 完整性校验

```
sum(cur_records[].count) + type_stats[].next_s_cur_times == type_stats[].total_count
```

6/6 频道实测成立。它校验的是**抽数**，比「金数对得上」更强。
另：`index.total_gacha_count` 与 `total_s_count` **都不含邦布**（实测 3714 / 62，六频道相加 5375 / 96）。
**邦布抽卡用的是邦布币，和调频券不是同一种货币**，所以跨频道的「总抽卡数 / 平均每金 / S 级总数」一律扣掉邦布，只统计同一货币的频道（`config.report.json` 里 `channels[].countsTowardTotals`）。邦布自己的每金成本在 KPI「每邦布」里单独给。

## 2. 首屏

- **标题行**：`昵称 · UID 胶囊 · 大标题 · 隐私开关（眼睛）`，右侧留白处放 **GitHub 仓库链接**，一行不换行。
  - **显示的是安装命令 `npx skills add atian25/zzz-stats`，不是裸 URL**，点击仍打开仓库。
    看到报表的人最可能想做的是装上它，一条能直接粘的命令比还要再翻 README 的地址有用。
    地址与文案在 `config/report.json` 的 `copy.repo`。
  - 文字前带 **GitHub 图标**（内联 SVG，`currentColor` 描边，13px），整行用 `inline-flex` 垂直居中。
  - 样式要低调：等宽小字、灰色，hover 时图标与文字一起变主题金色；`target="_blank" rel="noopener"`。
  - 只替换文字节点、保留图标（`#repo-text`），不要用 `textContent` 整段覆盖，否则 SVG 会被清掉。
  顺序是「先是谁，再是账号标识，最后是评价」——称号放最后，因为它是对这个人的结论，不是身份信息。
- **大标题**：按每 UP 均查 `config.report.json` 的 `titles.tiers`（10 档，见 §4）。**按公式算出再写**，不要写死。
- **次行四项**：`N 抽 总抽卡数 / N S 级代理人 / N UP 代理人 / N UP 音擎`，
  行尾灰色等宽小字 `国服 · 采集 YYYY-MM-DD HH:MM`。
  - **不要放版本区间**：版本在横轴上已经按柱标注了，行尾再写一遍是冗余。
  - **不要放 region**（`prod_gf_cn` 这类）：对读者没有意义，排查问题时看 `data/meta.json`。
  - **时间必须带年份**：跨年看报表时 `MM-DD` 会有歧义。
  - **前两项 = 全账号汇总**，口径是「除邦布外全部五个频道」，
    实测 `2372(UP) + 650(常驻) + 590(音擎) + 90(独家重映) + 12(音擎回响) = 3714`，
    与官方 `total_gacha_count` / `total_s_count` 完全一致（3714 / 62）。
  - **后两项 = UP 数**，取自官方 `type_stats[].up_count`（实测代理人 27、音擎 8）。
    **UP 写「UP 代理人 / UP 音擎」即可，不要再加「S 级」**——UP 角色的稀有度恒为 S，写了是废话。
  - **注意 41 ≠ 27**：41 是「独家」频道的全部 S（27 UP + 13 歪出 + 1 副金），62 是全账号全部 S。
    不要把 41 当 UP 数。
  - **用「代理人」而不是「角色」**：游戏内角色池抽出来的就是代理人，术语要跟游戏一致。
  - **不放「UP 池抽卡数」**：该数字在下方 KPI「每 UP 角色」的语境里已经隐含，首屏不必再占一格。
  - **界面上不要堆括注**（`不含邦布` / `含歪出` 之类）：口径写在本文件里，界面只给干净的四项。
  - **不要写「平均每金」这种跨频道混算值**：`3714 ÷ 62 = 59.9` 把不同频道的抽数合在一起除以总金数，
    等于假定它们在同一个计价体系，实际期望完全不同。各频道真实成本看下面的 KPI。
- **KPI 固定 5 格一行**（窄屏也不折行）：`角色池不歪 / 每 UP 角色 / 每 UP 音擎 / 常驻每金 / 每邦布`。
  这 5 个数全部按「扣垫抽」口径算（见 §1），不要退回含垫抽的总抽 ÷ 金数。
- **隐私开关**：称号右侧的眼睛按钮（UID 胶囊只负责显示），**三态循环**（默认全显示）：① 全显示 → ② 仅打码 UID（`UID 116***92`）→ ③ 全打码（昵称只留首字 + UID 打码）→ 回到 ①。图标用内联 SVG 三态。
  **对外截图必须先点到全打码（从默认点 2 下）。**
  - **这条不是提醒，是硬约束。** 已经踩过一次：README 的预览图连着两版把真名和 UID
    截进了公开仓库，事后才发现。截图脚本里必须先
    `eye.click(); eye.click();`，再断言 `#eye` 的 `data-state === '2'` 与
    `#nick` 含 `*`，断言不过就**中止截图**——宁可没有图，也不要一张带真名的图。
  - 打码版一旦提交、推送就收不回来了：`git show <旧commit>:docs/preview.png` 永远取得到。
    所以这一步只能在截图前做对，事后补救是补不回来的。
- `document.title` 也要跟着三态变，否则标签页会泄露昵称、或与页面状态不一致。
- **验证隐私开关时不要用已打码的昵称做数据**：`maskName('天*')` 仍返回 `天*`，
  看起来像「点了没反应」。测试数据里要放完整昵称，才能验证状态 2 真的把名字盖掉。

## 3. 主图（`抽卡总览`）

### 3.0 配色语义（值在 `config.report.json` → `colors`）

颜色不是装饰，每一个都对应一个判定，换色等于换语义：

| 含义 | 色值 |
|---|---|
| 极欧 ≤ 40 抽（本发上段） | 蓝 `#3F7BFF` |
| 极欧周期的歪段 | 深蓝 `#1B3C78` |
| 欧 > 40 抽（本发上段） | 深绿 `#2E8F45` |
| 欧周期的歪段 | 深绿 `#1B5E2A` |
| 非酋本发上段（超均值） | 亮红 `#FF5F6D` |
| 非酋歪段 | 深红 `#A81E28` |
| 累计不歪率折线（非酋 <35%） | 红 `#FF8A94` |
| 累计不歪率折线（薛定谔 35~50%） | 绿 `#5FD98A` |
| 累计不歪率折线（大欧 ≥50%） | 蓝 `#7FB4FF` |
| 折线描边（三档共用） | 深色 `#0d0d10` |
| 十连多金圆点 | 青 `#7BE0FF` |
| 版本分隔虚线 | 灰 `#3A3A42` |

**堆叠柱的读法**：下段 = 歪掉的抽数，上段 = UP 本身。**柱体颜色表达运气（欧/非），不表达 50/50 输赢**——
「歪」只在第二屏用红章标出。这两件事不要混在一根柱子上表达。

### 3.1 版式

- 面板标题 `抽卡总览`（15px/700），右侧灰字 `N 个 UP · N 抽`。
  - **主图支持切频段**：标题右侧是频段 tab（独家 / 音擎 …），与第二屏的 `.detail-tab` 同一套读法（金色下划线＝选中）。
    只渲染**有 50/50 且真的折出了 UP 轮**的频道；常驻/邦布没有 UP 概念，复刻池常为 0 轮，都不给 tab（点进去全空的 tab 比没有更差）。
    只有一个频道可画时整条 tab 不渲染。
  - **为什么音擎要切数据集而不是加成柱子**：音擎保底 80 抽、每 UP 抽数也自成一套，并进角色池的柱子会让两边的「超出均值」判定都不成立。
  - **版本过滤**（`1.x` / `2.x` / `3.x`，多选）：只列该账号真实出现过的档位，不写死。
    全部取消＝回到全显示（不是画空图）。切换频段时**保留**过滤选择——两个频道共用同一套版本号。
    形态是「漏斗图标 + 带勾选态的标签」：外层 chip 无框无底，内层是 12×12 的细框勾选框；
    选中是「灰框 + 勾」，未选中是「灰框 + 短横」。
    **勾选框那个方框不能删**——它是「这里可以勾」的唯一视觉暗示，删了整排就退化成一行说明文字。
    **选中态不能用金色**：`--accent`（金 `#F5C04A`）在这份报表里代表「欧气/好运」（`tag[data-tone="positive"]` 就用它），
    过滤器勾上 ≠ 好运，用金色是错误暗示。金色留给 tab 选中态（那是「你在看哪个」，与运气无关）。
    **区分也不能只靠颜色差**（早先就是实心金色 chip vs 灰描边，压成灰度后分不出来）；
    勾 vs 短横是形状差异，压色、缩小都还认得出来。
    icon 必须是**内联 SVG**，不能引外部图标库——产物要能单文件离线打开。
    窄屏（≤720px）过滤条换行独占一行并允许横向滚动，否则会被面板右边裁掉、点不到。
  - **不歪率折线始终按「全局累计」算，版本过滤只缩柱子、绝不重算折线。**
    这是用户定死的口径，**不要改**。原因：过滤是为了「只看 2.x 那几根柱子」，
    如果折线也跟着重新累计，同一根柱子在不同过滤组合下会落在不同的折线高度上，
    读者会以为数据自相矛盾；折线表达的是「这个号一路走来的整体水平」，不该随筛选变化。
  - 不过滤时右侧写官方口径的该频道总抽数（`chart.pulls`），**不要用柱子求和**——两者差的是垫抽（实测 6320 官方 vs 6318 柱和）。
    过滤生效后改写 `{shown} / {upCount} 个 UP · {pulls} 抽`，其中 pulls 是可见柱之和，否则数字和图对不上。
- **堆叠柱**：下段 = `off`（歪掉的抽数），上段 = `up`（含十连副金）。**柱顶**写本轮总成本；**柱内**各段写各自抽数（段 < 8 抽不写）。
- **柱宽必须同时设百分比和像素上限**：`barWidth: '46%'` 的百分比基数是**类目带宽**，不是画布宽度。
  柱少时类目带宽变大，46% 会撑成巨型色块——实测复刻角色只有 1 根柱时宽 **600px**，而 71 根柱时每根只有 96px。
  所以两段柱（`off` / `up`）都要加 `barMaxWidth`，取值走 `config/report.json` 的 `numbers.barMaxWidth`（默认 56），
  改配置就生效，不要在 JS 里另写死数。**两段必须同值**，否则同一根柱的上下段宽度不一致，会错位成阶梯形。
- **不歪率折线按三档分色，红 / 绿 / 蓝与柱体同语义**（`config.numbers.winRateTiers` + `colors.winRate*`）：

  | 不歪率 | 判定 | 折线颜色 | 对应柱体色 |
  |---|---|---|---|
  | `< 35%` | 非酋 | 红 `#FF8A94` | bad 红 `#FF5F6D` |
  | `35% ~ 50%` | 薛定谔（还没定型） | 绿 `#5FD98A` | good 绿 `#2E8F45` |
  | `>= 50%` | 大欧 | 蓝 `#7FB4FF` | extreme 蓝 `#3F7BFF` |

  - **两套颜色是同一套语义的两种亮度，不是两套配色**：
    柱体的红/绿/蓝表达「这一轮差于均值 / 好于均值 / 极欧」，
    折线的红/绿/蓝表达「这个号在此刻的累计水平是非酋 / 还在薛定谔带 / 大欧」。
    都遵循「红<绿<蓝＝从差到好」同一条阶梯，读者不需要学第二套读法。
  - **折线必须用同色相的提亮版，不能直接复用柱体色值**：折线会横穿柱子，
    同色时对比度只有 1.0~1.4（实测红折线过红柱 1.00、绿折线过绿柱 1.00、蓝折线过蓝柱 1.00）——
    压在柱子上等于看不见。提亮后对柱体 1.5~2.3、对底色 7.7~10.9，既认得出是同一档，又压得住。
    色值键是 `colors.winRateUnlucky` / `winRateSchrodinger` / `winRateLucky`（对应 `numbers.winRateTiers` 的三个 key）。

  - **提亮不够，折线还必须加深色描边（halo）**。提亮版压在**同类柱子**上仍然低于 3:1：

    | 折线 | 压在同色柱上 | 判定 |
    |---|---|---|
    | 红 `#FF8A94` | 红柱 `#FF5F6D` | **1.31 : 1** |
    | 绿 `#5FD98A` | 绿柱 `#2E8F45` | **2.30 : 1** |
    | 蓝 `#7FB4FF` | 蓝柱 `#3F7BFF` | **1.80 : 1** |

    三档全部低于 3:1，且是**最该看清的那一段**（自己的累计水平正好落在自己那一档的柱子上）。

    做法：**同一段线画两遍，先粗后细**。粗的那遍用深色 `colors.winRateHalo`（`#0d0d10`，与 tooltip 底色同值），
    细的那遍才是彩色线。彩色线 1.4px、描边 4.6px，两侧各露出 1.6px。
    **1.6px 这个数字不能改小**：取 3px 时每侧只有 0.8px，属亚像素，抗锯齿会把描边和柱色混成一团，
    实测紧邻对比度只有 1.09~1.47，与没加描边（1.31）几乎一样，等于白做。
    圆点同样画两遍（描边圈 r=4.2、彩点 r=2.6），否则线头会从节点两侧露出来。

    实测（天猪 1440×900 截图像素，按「线的紧邻像素」分类统计）：

    | 折线 | 紧邻描边时 | 描边覆盖率 |
    |---|---|---|
    | 红 | 中位 **5.67 : 1**，最小 2.80 | 78% |
    | 绿 | 中位 **9.13 : 1**，最小 5.66 | 97% |
    | 蓝 | 中位 **6.69 : 1**，最小 3.10 | 91% |

    剩余未覆盖的像素集中在**柱子顶部的抗锯齿边缘**（线恰好压在柱顶那一两行上），描边被柱子的边缘像素吸收。
    这部分无法靠加粗解决，只能靠加宽——但再加宽就会把柱子挖出一条明显的黑沟，得不偿失。

    **为什么不用另外两个方案**：
    - **加半透明底衬**会弄脏柱子：一块 40% 不透明的黑色蒙版压在柱子上，柱子本身的颜色就没法读了，
      而柱子颜色是「歪掉的抽数 / UP 抽数」的语义，不能为折线让路。
    - **换更亮的绿**只解决绿色档，红蓝两档仍然低于 3:1（它们本来就比绿更亮，没有提亮空间）。
      而且三档亮度拉开后，就不是「同一条阶梯」了。
    - 描边色取**实色深色**而不是半透明黑：半透明会吃进柱子的色相，在红柱上偏红、在绿柱上偏绿，
      三档分开后描边本身又变得不一致。

    **描边在深色柱段上会糊，这是已知且可接受的局限**：

    | 描边 `#0d0d10` 压在 | 对比度 |
    |---|---|
    | 红柱浅色上段 `#FF5F6D` | 6.57 : 1 |
    | 绿柱浅色上段 `#2E8F45` | 4.74 : 1 |
    | 蓝柱浅色上段 `#3F7BFF` | 5.07 : 1 |
    | 红柱深色下段 `#A81E28` | **2.66 : 1** |
    | 绿柱深色下段 `#1B5E2A` | **2.48 : 1** |
    | 蓝柱深色下段 `#1B3C78` | **1.82 : 1** |

    深色下段那三行低于 3:1，描边几乎糊进柱子里。**但这一档本来就不需要描边**：
    彩色线压在深色段上本身就有 3.23 / 4.09 / 4.39（红/绿/蓝），全部达标——
    会「看不见」的是浅色上段（1.31~2.30），而那正是描边起作用的地方。
    换句话说，描边的有效区间与需要它的区间正好重合。

    想把深色段也拉开，只能把描边改浅（那会在浅色段失效）或加半透明底衬（会弄脏柱子），
    两个都更糟。**所以这一条不要「修」**。

  - **50% 是 50/50 的理论期望**，天然是「欧／不欧」的分界；**35% 是「明显低于随机」**，标出真的差的段落。
    中间那档早先是**中性灰**（`#8A8A96`），换红绿蓝后改成绿色：灰的问题是它在深色底上
    和红柱对比只有 1.15，被柱子淹没（用户原话「这个折线图有 3 个颜色么？我看不太清」）。
  - **跨界线段整段按较高一端的档位着色**：一段连线两端是 30% 和 40% 时，整段取 `Math.max` 落档。
    「这段有没有跨过上一档」比「这个点落在哪档」更贴近读数习惯。
  - **不能用 `line` + `visualMap` 实现**：`visualMap` 的 `pieces` 按数据点判色，
    ECharts 会在相邻两点之间用两端颜色做渐变过渡，做不到「整段同一色」。
    必须用 `type: 'custom'` 自己画：每条线段由左端点负责画，圆点按自身值单独定色。
  - 折线 `z` 要高于柱子（3）、低于头像（4）与多金点（5），否则会被柱体压住。
  - 折线的蓝（`#7FB4FF`）与「蓝＝极欧 ≤ 40 抽」的柱（`#3F7BFF`）同色相、不同亮度，靠亮度区分。
- **柱顶头像栈**：每根柱顶上摞该轮涉及的所有金（**头像 22px，层间距 23px**），**先出的在上、后出的在下**。叠放顺序是「歪出角色 → UP → 十连副金」：歪出的先出，所以在最上层；十连副金在 UP 之后出，所以在最下层。
  **歪出的角色必须画出来**——只画 UP 会让「这一轮歪了谁」在图上消失。实测 27 根 UP 柱里有 13 根带歪出头像，加上 1 个十连副金，柱顶头像总数 = 41 = 全部金数。
- **柱顶总抽数**：写在该柱头像栈的**正上方**，不能被头像压住；头像层数不同，所以每根柱的偏移量要按自己的层数算。
- **两个坐标轴都固定，不按数据自适应**（`config.numbers.axisPullsMax` / `axisWinRateMax`）：
  - **左轴（抽数）按频道固定**：角色池 / 常驻 / 复刻 **0~180**，音擎 / 回响 / 邦布 **0~160**。
    取值依据是「该频道保底 × 2」：一轮 UP 的成本最多是「先歪一次吃保底 + 再吃保底」。
    自适应的问题很直接——天猪号最高柱 159、音擎最高 137，各自缩放后两张图的柱子看起来一样高，
    读者读不出谁更高。固定之后跨账号、跨频道都能直接比。
  - **右轴（不歪率）固定 0~100%**：不歪率的理论范围就是 0~100%，没有按数据缩放的道理。
    固定后 35% / 50% 这些分界线在任何一张图上都落在同一高度，档位读法统一。
    代价是曲线只占下半幅（实测大欧号终值 56.3%、非酋号 48.1%），但那才是真实水平。
  - 早先两个轴都做过自适应（左轴 `ceil((max+18)/30)*30`、右轴「峰值 + 10%」），
    那是把「单图好看」放在了「跨图可比」之上，已废弃。
- **红柱 ≠ 歪**：红是「超出该账号每 UP 均」（非酋），绿/蓝是欧。真正的 50/50 结果看「歪」章（在详情里）。
- **累计不歪率按三档分色**（红→绿→蓝），和柱体同一套语义，见 §3.0 与下方分档表。
  右轴**固定 0~100%**，不按数据自适应（见上条）。早先这里写过「金色折线 + 右轴自适应」，已废弃。
- **右轴下限就是 `0`，和 x 轴基线对齐，不要抬到负值。**
  0% 的意思是「一次都没赢过」，它本来就该坐在基线上。早先试过留 -4% 负余量
  去换「看得见」，结果 0% 那条线被抬离基线，读者反而要猜「这条线到底是不是 0」——
  **不能拿坐标语义去换可见性。**
- **贴底可见性用这三条解决，都不动坐标语义**：
  1) `z` 高于柱子（见下条），否则线被柱体压住，整段消失；
  2) 折线 `clip: false`，描边不裁进 grid，贴底时不会被切掉一半；
  3) 柱子画在线的下面，线在基线附近依然是完整的。
- **折线的 `z` 必须高于柱子的 `z`（柱子默认 2，折线设 3）。**
  两者同级时折线会被柱体压住，曲线一进到柱子范围内就看不见——
  表现为「曲线从中间才开始，前面那几根柱子没有线」。
  用户会以为数据缺失，实际是图层顺序问题。3 高于柱子、低于头像（4）与双金点（5），
  既能整段可见，又不会骑到角色脸上。
  - 两个问题要分清：**z 太低**＝线被柱子挡住（整段消失）；
    **0% 贴底**＝线在柱子外面也看不见（只影响 0% 那几段）。两个都要修。
- **不画版本分隔竖线。** 早先版本用贯穿全图的灰色虚线标版本切换，但柱顶头像是摞在柱子上方的，
  竖线一定会插进头像和总抽数里，噪音大于信息。横轴本身按版本标注（`v1.0` / `v1.1`），分界已经看得出来。
- 横坐标写 `v1.0`、`v2.7`（**带 v**），**同一版本多根柱时只标一次、标在该版本那一段的中间**。
  逐柱都写版本号会变成 `v2.0 v2.0 v2.0` 一片——既读不出它们同属一个版本，也挤掉了相邻真正不同的版本。
  实测 71 轮 UP 的账号，去重前横轴 71 个标签糊成一片，去重后是 14 个版本号。
- **版本号的画法（用户定死的口径，改之前先问）**：
  - **版本号画在「线里面」**，也就是夹在 x 轴与横线之间（`textY = 轴 + 11`，横线在轴下 22）。
    读者看到的是「一条横线 + 两端竖虚线，版本号被框在中间」，而不是版本号飘在线外面。
  - **多柱版本**：一条横线 + **两端竖虚线**把版本号框住，版本号**真正居中**。
    居中必须取 `(首柱 x + 末柱 x) / 2` 自己算——`axisLabel` 只能把文字挂在某个柱心上，
    2 根柱的中点落在两根之间（x.5），挂哪一根都会偏半格。所以版本号、横线、虚线全部由 `custom` 自绘。
  - **单柱版本**：只显示版本号，**不画任何线**。单柱没有「跨度」，两端竖虚线会退化到同一个 x 上（看起来像一条粗线），
    横线也没有左右可延伸。早先试过给单柱加一个「横托」，结果托的宽度和实际柱宽对不上，看起来是歪的。
  - **只有一个数字时不要偏移**：单柱版本的版本号必须正对柱心，左右都不能偏。
  - 竖虚线要够长（实测 ≥18px）才画得出虚线感：短了只剩一段 dash，看起来还是实线。
  - 竖虚线只提示范围边界，**不做封闭括号**（早先做过开口朝上的 U 形，用户否掉了）。
- **图例固定 4 条，单行**：红＝超出均值 · 深色段＝歪掉的抽数 · 蓝＝极欧 ≤ 40 抽 · 绿＝欧。
  只留「光看图看不出来」的语义。**不要**把「柱顶＝总成本」「柱内＝各段抽数」「头像先出的在上」这类自解释的东西写成图例——那会把注脚变成说明书。
  行尾原来的灰字「官方接口 · N 条 S 记录」（`copy.legendTail`）已按用户要求删除，图例不再有右侧尾注。
- **折线三档不进图例**：折线靠自身颜色（红/绿/蓝三档）和右轴刻度就能读，青点的大小已经编码金数、tip 里也写了完整链路。
  两条都写进图例会让注脚变成说明书。实测去掉后图例只剩 4 条，单行放得下。
- **首屏无滚动**：1440×900 与 1280×800 都要首屏装下、图例单行；详情在第二屏，首屏底部不露出详情边线。
- **两张卡必须等宽、左右边界对齐**。主图在 `.screen` 内（该容器自带左右 20px 内边距），
  详情卡在 `.screen` 之外，**必须补同样的水平外边距**（`margin: 0 20px`），否则详情会顶到视口两边。
- **详情行悬浮高亮的是这一行自己**，不是联动上方主图。
  - 用 `:hover` 给整行加淡背景（`rgba(240,240,241,.07)`），左右各外扩 6px，
    让高亮像一条整宽的横带，而不是只包住图标和条（后者看起来像「选中了图标」）。
  - 同时把条轻微提亮（`filter: brightness(1.12)`），行背景和条一起强调。
  - 纯 CSS 即可，不要写 JS 去操作 ECharts —— 详情行和柱子数量本来就不一一对应
    （逐金 41 行 vs 主图 27 柱），跨面板联动只会误导。
- **主图可折叠，默认展开。** 折叠是为截图服务的：把主图收起来后 `.screen` 不再撑满 100vh，
  详情顶上来，顶部信息 + 详情能进同一屏（实测 1440×900 下一屏可见 20 行详情）。
  - 折叠**只收外层容器高度**（`.chart-main { height:0; overflow:hidden }`），
    **绝不对 `#chart` 用 `display:none`**——那会让 ECharts 读到 0 尺寸，展开后画布塌掉。
  - 展开时**不要重建图表**，只需 `chart.resize()`。`#chart` 的 display 始终是 block，
    容器尺寸恢复后 resize 即可还原，实测 `instH` 全程不变。
  - 按钮放在面板头右侧（`.panel-meta` 之后），箭头 0° ↔ 180° 旋转，文案「收起 / 展开」。
- **面板标题要垂直居中**：`.panel-head` 用 `align-items: center`，不要用 `baseline`——
  标题（15px 粗体）与右侧灰字（11px 等宽）基线不同，用 baseline 会让标题视觉偏下约 5px。

### 3.2 tooltip（axis trigger）

formatter 返回的是**纯文本多行**，必须显式保留换行：`extraCssText: 'white-space: pre'`
（ECharts 默认会把 `\n` 折叠成空格，表现为「换行没了」）。

```
猫又 → 南宫羽                  ← 歪出/副金在前，UP 在后；无歪时只写 UP 名
卡池 v2.7 · 2025-03-15 21:34   ← 版本后接该 UP 出金时间（record_time 转本地时区）
总共 44 抽，直出                ← 未歪
总共 52 抽，大保底，上个池子歪了「猫又」   ← 保底获得（guar）
总共 108 抽，大保底，37 抽歪「11号」      ← 歪了
本发十连多金                    ← 仅该发是多金；逐金分档见 §5
似非实欧，白赚大保底             ← 十连副金且本轮直出
累计不歪率 50%                  ← 永远最后一行
```


### 3.3 垫抽（保底进度）

垫抽 = 「离下一个 S 还垫了多少抽」，来自官方 `type_stats[].next_s_cur_times`。数据一直在落盘，
但过去 0 处展示——而这恰恰是玩家最想看的数。

- **只在第二屏「抽卡详情」里出现，作为正文的一行**，造型照官方调频页：
  **左边金色问号方块**（下一个 S 未知）+ **右边绿色斜纹条**，条内写 `已垫 N 抽`。
  **条右侧不要写 `/90`**：保底上限属于悬浮才需要的细节，常驻显示会把一行变成三个数字，
  反而看不清主次。上限只在 tip 里出现。
- **主图（抽卡总览）不放垫抽。** 主图讲的是「历史每一轮的成本」，垫抽是「当前这一档的状态」，
  两种时间视角混在一个面板头里会让人以为柱子也算进了垫抽。
- **不要放在面板头上**。详情头的横向空间要挤 6 个频段 tab + 勾选框 + meta，
  再塞一条进度条，两边都看不清；而且垫抽和下面的金条是同一套「长度＝数值」的读法，放正文才连贯。
- **放在最新版本组内部的第一行**，不是列表外面。外面那层没有版本括号的缩进
  （1px 括号 + 7px gap + 版本号宽度 ≈ 42px），放外面问号块会比下面的头像整体左移 42px，一眼看出没对齐。
- **上边距要比普通行大（8px）**：这一行紧贴 tab 下划线，26px 的问号方块会被那条金色下划线视觉压住。
- **不要给这一行加分隔线**（`border-bottom` / `<hr>`）。它就在 tab 下划线正下方，
  再加一条横线会被读成「当前频段的第二个下划线」，而且横线铺满整行、比 tab 下划线长得多，像页面分割线。
  用 `margin` 留白分隔即可。
- **该频段进度为 0 时不画**（如独家 / 音擎：刚出完金或没垫）。显示一条空条只会让人以为坏了。
- **空频段也要画**（如音擎回响：垫了 12 抽、一金未出）。只写「这个频段还没有 S 级记录」
  等于把唯一有信息量的数藏起来。
- **保底上限在 `config/report.json` 的 `channels[].pityCap`**，按频段不同（见 `references/api.md` §5）：
  常驻 / 独家 / 独家重映 90，音擎 / 音擎回响 80，邦布 80。
  **不要用 `new_s_max_times`**：那是官方 UI 的区间展示值，不是硬保底
  （实测常驻该值 32，而该频道最长出金间隔是 80）。
- **剩 ≤ 10 抽时条变红**（`.pity-row[data-near="true"]`），表达「马上就要出了」。
- **悬浮显示「保底上限 + 上一个 S」**：行内只有「已垫 58 抽」，读者要知道还差多少、
  从谁开始垫的，都在 tip 里：`已垫 58 抽，还差 32 抽到保底（90 抽保底）` + `上一个 S：啜泣摇篮（v3.1）`。
  整条频道还没出过金时后半行不出现。
- **口径只在 `build-report.mjs` 算一次**：`{cur, cap, remain, pct, last}` 由构建产出，前端只负责画。

## 4. 称号（`config.report.json` → `titles.tiers`）

基准：角色池每 UP 期望 = 62.5 抽/金 × 1.5（50/50）= **93.75 抽**。

**大标题要能悬浮查看完整档位。** 鼠标移上去显示全部 10 档区间，**当前档加粗高亮**，第一行写清本账号的判定：

```
每 UP 均 87.9 抽 → 欧气满满大欧皇

≤ 62.5      终极无敌至尊欧皇
62.5 – 80   万里挑一至尊欧皇
80 – 90     欧气满满大欧皇      ← 这一行加粗 + 主题金色
90 – 95     欧非守恒
...
> 125       终极无敌至尊非酋

按「角色池每 UP 均（含歪）」判档
```

- 区间文案要**算出来**（`prev ~ maxPullsPerUp`），不要在提示里手写死。
- 当前档靠比对 `tiers[].name` 命中，不要按索引猜。
- **加粗 + 颜色表示命中的那一档**，不要用 `▶` 之类的符号前缀。
- 光标用 `pointer`（与 Tag、详情行一致，同是手形），**不要用 `cursor: help` 的问号光标**。
- 标题要给出可悬浮的**视觉暗示**，但**不要用虚线下划线**（像超链接，观感廉价）：
  hover 时用主题色柔光（`text-shadow` + `brightness`）即可。
- 气泡样式与图表内 tip 保持一致（同一个 `.tip` 组件）。
- 因为要加粗，这条提示走 `data-tip-html`（内容需转义后再拼 `<b>`）；其余提示仍走纯文本 `data-tip`，避免 XSS 面。

档位来自 2026-11 收集的 12 条工坊「抽卡总结」样本拟合，**不是人群百分位**；不歪率只是强相关，不能当判据。

| 每 UP 均 | 称号 |
|---|---|
| ≤ 62.5 | 终极无敌至尊欧皇 |
| ≤ 80 | 万里挑一至尊欧皇 |
| ≤ 90 | 欧气满满大欧皇 |
| ≤ 95 | 欧非守恒 |
| ≤ 99 | 欧气附体小欧皇 |
| ≤ 105 | 欧气不足小非酋 |
| ≤ 110 | 薛定谔的非欧 |
| ≤ 117 | 超级至尊非酋 |

改档位只改 `config/report.json`，`tiers` 按 `maxPullsPerUp` 升序、最后一项用 `null` 兜底。

## 5. 标签（`config/report.json` → `tags.rules`）

规则是**数据驱动**的：每条 rule 有 `kind`（`metric` / `series` / `event` / `round`）、条件、配色和提示模板。条件不满足就不出现，不要为了好看硬凑。

| 标签 | 触发 |
|---|---|
| `欧气附体` | 十连双金 ≥ 1 次，或极欧柱 ≥ 2 根 |
| `运势极佳` | 最长连 UP ≥ 4 |
| `时运不济` | 最长连歪 ≥ 3（负向） |
| `非酋附体` | 每 UP 均 > 110（负向） |
| `代理人 K 连 UP ×N` | 连续直出段；**每个不同长度各出一个标签**，同一长度出现多次才加 ×N；**保底获得要打断连 UP** |
| `代理人 K 连歪 ×N` | 连续先歪段；同样是每个长度各出一个标签 |
| `十连双金 ×N` / `十连 3 金` / `十连 4 金` | 十连多金组，**按一组的金数分档**，不写人名；**tone 用 positive（金）** |
| `似非实欧 ×N` | 先歪但总抽 < 该账号每 UP 均；蓝色 |
| `非酋翻身记` | 曾经真掉进非酋档（谷底 `< 35%`）、现在爬出来了（终值 `>= 35%`）、涨幅 `>= 15pp` |
| `薛定谔的非酋` | **曾经**在非酋和欧之间来回横跳（完整窗口序列内非↔欧切换 `>= 2` 次）；中性灰 |

### 5.2 轨迹标签（`非酋翻身记` / `薛定谔的非酋`）

这两个标签看的是**累计不歪率的走法**，不是终值。终值只差 8pp 的两个号，走法可以完全相反。

**为什么不能只看终值**：实测天猪号 48.1%、joker 号 56.3%，只差 8 个百分点，
但天猪是「从 14.3% 一路爬上来」，joker 是「一路在 70% 和 20% 之间起伏」。

**横跳的分界线不是 50%**。这是最容易搞错的一点：50% 是**小欧和大欧**的分界（50~65 小欧、>= 65 大欧），
两边**都是欧**，在 50% 上下浮动不代表横跳。真正的横跳是**在非酋和欧之间来回**：
`nonEdge`（35%，非酋档上界）以下算非、`euroEdge`（50%，理论期望）以上算欧，
中间那条「薛定谔」带（35~50）两边都不算 —— 它本来就是「还看不出来」的地带，在里面游荡不算横跳。

**横跳必须在滑动窗口上算，不能看累计值**。累计是全程平均，早年的坑会被越摊越淡：
joker 号的累计谷底是 42.9%，**从没进过非酋档**，按累计值算横跳次数是 0 —— 但它显然在来回跳。
把窗口收到 10 轮就看出来了：窗口内胜率一路从 70% → 20% → 80%（实测切换 2 次）。
注意这是**该号 v1.2～v1.4 那一段的历史**，不是它现在的状态——第 27 轮之后窗口一直稳定在 50~80%。
所以 `winRateShape()` 在 `rollingWinRate()` 的序列上数切换，而标签文案必须带出版本区间与距今轮数。

**`minSamples` 门必须加**：前几轮的累计值是噪音。1 轮 0%、2 轮 50% 这种极值会把谷底拉到 0%，
于是每个新号都能自称「曾是非酋」，标签直接烂大街。默认从第 5 轮起算
（天猪前 3 轮都是 0%，排除后谷底落在第 7 轮 v1.5 的 **14.3%**）。

| 实测 | 谷底 | 终值 | 涨幅 | 非↔欧切换 | 命中 |
|---|---|---|---|---|---|
| 天猪（27 轮） | 14.3% @v1.5 | 48.1% | +33.8pp | 1 | `非酋翻身记` |
| joker（71 轮） | 42.9% @v1.4 | 56.3% | +13.4pp | 2 | `薛定谔的非酋` |

**两条标签不互斥**（用户明确要求）：一个号可以既翻过身、又一路来回跳。

#### `flips` 是历史事件，不是当前状态

`flips` 在**完整窗口的全序列**上统计（`rollingWinRate(bits, window).slice(window - 1)`，
从第 `window` 轮一直数到最后一轮），**不是只看最近几轮**。所以这个标签描述的是「**曾经**来回过」。

实测 joker 号：2 次 flip 落在第 20 轮和第 27 轮（共 71 轮），**距今 44 轮**；
按最近 30 个窗口算，flips 早已回到 0。

因此文案**必须**带出版本区间与距今轮数：

> `不歪率曾在非酋和欧之间来回横跳 2 次（v1.2～v1.4），最近一次在 44 轮前`

- **不许写「近期」**。写着「近期胜率在来回跳」，实际指的是 44 轮前就结束的事，
  读者会以为这个号现在还在剧烈波动——措辞把历史事件说成了当前状态，是**事实性错误**。
- **必须点明是「不歪率」**，且逐条明细里要写「**近 N 轮**不歪率」，不能只写「窗口」或光秃秃一个百分比。
  「窗口」是算法内部说法（`rollingWinRate()` 的窗口长度），读者不知道在量什么；
  不写「近 N 轮」则会被当成**累计**不歪率，拿去和顶部 KPI 的 56.3% 比，然后发现对不上——
  这两个本来就是不同的量（joker 累计谷底 42.9%，近 10 轮却能掉到 20%）。
- 对应指标：`winRateFlipFromVersion`（首次 flip 的版本）、`winRateFlipToVersion`（末次 flip 的版本）、
  `winRateFlipToAgo`（`总轮数 - (末次 flip 轮索引 + 1)`）。
- **下标必须换算回轮索引**：遍历的是 `slice(window - 1)` 之后的切片，
  循环变量是「切片内第几个」，真实轮索引是 `i + (window - 1)`。
  用错会整体前移 9 轮——实测 joker 会算成 v1.1～v1.2、53 轮前，正确的是 v1.2～v1.4、44 轮前。

#### tip 必须逐条列出每次横跳的具体数值

只写「来回 2 次」看不出**跳幅**：从 55% 掉到 30% 再弹回 52%，和 49%↔51% 来回蹭，
次数一模一样，含义完全不同。所以 tip 第二行开始逐条列出每次 flip：

> ```
> 不歪率曾在非酋和欧之间来回横跳 2 次（v1.2～v1.4），最近一次在 44 轮前
> v1.2 第 20 轮 欧 → 非：近 10 轮不歪率 50% → 30%，最低 20%
> v1.4 第 27 轮 非 → 欧：近 10 轮不歪率 30% → 50%
> ```

每行四个必填项 + 一个条件项：

| 项 | 来源 | 说明 |
|---|---|---|
| 版本 | `charRounds[flip.idx].version` | 「哪一版」 |
| 轮次 | `flip.idx + 1` | 「第几轮」，1 基（用户数轮次从 1 开始） |
| 方向 | `from` / `to`（±1） | 汉字「欧 → 非 / 非 → 欧」，不用箭头字符（等宽字体下宽度不稳，多行会歪） |
| 读数 | `prevWinRate` → `winRate` | **两侧读数**，且必须冠以「近 N 轮不歪率」，见下方 |
| 最低（条件） | `low` | 仅「掉进非酋档」那一条才写，且 `low < winRate` 时才有意义 |

**读数必须写明「近 N 轮不歪率」，不能只写「窗口 50%」。**
`N` 取 `winShape.window`（配置 `numbers.winRateShape.window`，默认 10），**不要写死**。
理由见上一节：不点明指标名读者不知道在量什么，不点明「近 N 轮」会被误当累计值。

**起点必须取「同档最后一次读数」，不能取上一轮的值。**
两次 flip 之间可能隔着几轮薛定谔带（35~50 不计数），上一轮的值未必属于同一个档；
硬拿上一轮的值当起点会写出一个从没真实出现过的数字。
实现上维护 `lastOf = { '-1': ..., '1': ... }`，每次读到有效档位就更新，
flip 发生时取对面那个档位存着的值。

**「最低」只在掉进非酋档的段落里算**：从这次 flip 起向后扫到下一次 flip（或序列结束），取窗口最小值。
这个是横跳里最有信息量的数——joker 的**累计**谷底是 42.9%（从没进过非酋档），
但 10 轮窗口实打实掉到过 **20%**，只说「掉进非酋档」读不出掉得多深。

指标名：`winRateFlipList`（`\n` 分隔的多行文本，空时为 `''` 而不是 `null`——
tip 模板里 `{winRateFlipList}` 若为 null 会渲染出字符串 "null"）。
气泡是 `white-space: pre`，直接换行显示，不需要 `<br>`。

#### 非↔欧的分界是 35% / 50%，不是 50% 一条线

- `< 35%` 算**非酋**，`>= 50%` 算**欧**，中间的 35~50 属于「薛定谔」带，**两边都不算**（不计数）。
- **50% 是小欧/大欧的分界，不是横跳线**。50~65 小欧、>= 65 大欧，两档都在欧这一侧，
  在 50% 上下浮动不属于横跳——这是最容易写错的地方。
- 判定要求窗口**真的进出非酋档**（`< 35%`），在小欧/大欧之间浮动不算。

阈值全在 `config.numbers.winRateShape`（`nonEdge: 35` / `euroEdge: 50` / `oscillationFlips: 2` / `window: 10` / `minSamples: 5`），改配置就生效。

**标签配色按语义分四档**（`config.report.json` → `tags.rules[].tone`）：
`positive` 金（好运：欧气附体、连 UP）· `negative` 红（坏运：连歪、非酋附体）·
`info` 蓝（极欧柱）· `neutral` 青（预留，**十连多金的记号色，不要拿来当语义色**）·
`shrodinger` 中性灰 `#8A8A96`（「薛定谔的非酋」）· `highlight` 亮金 + 外发光（**最高光事件**）。
注意这个灰**不再**和折线中间档同色：折线中间档已改成绿色 `#5FD98A`（见 §3.0），标签的灰是独立语义。

**两类标签用 `highlight`**：
- **最长的那条连 UP**（`id` 不带后缀的那个）。一个账号同时有 5 连、4 连、3 连时，
  它们同为常规金色，读者看不出哪条是最高纪录。
- **所有「十连 N 金」**。这是整份报表里最罕见的事件，和普通连 UP 同色会被淹没。

**连歪绝对不能用 highlight**。它和连 UP 走同一段代码，同样有「最长的一条」，
若只按 `idx === 0` 提亮，「代理人 7 连歪」这种最霉的纪录会被高亮成主角，语义完全反了。
判据要带上 `rule.tone !== 'negative'`。

**只换颜色不够**：两个金在深色底上只差几个色阶（实测 `#F5C04A` vs `#FFE066`），
必须有同色外发光（`box-shadow` 两层：1px 描边 + 12px 光晕），才一眼看得出主次。

**多金必须按金数分档，不能一律叫双金。** 一组多金的金数由「同秒且 `sort` 差 ≤ 9」的连续金决定，可能是 2 金、3 金，甚至 4 金：

- **统计范围是「角色池 + 音擎」两个频道合并**，不是只算角色池。
  只统计角色池会漏报：实测 joker 号角色池 5 组、音擎另有 2 组（一组三金、一组双金），
  漏掉音擎会让标签写「双金 ×4 / 3 金」，正确是「双金 ×5 / 3 金 ×2」。
- **合并前必须按频道分段再各自成组**：`sameTenPull` 判的是「同秒 + `sort` 差 ≤ N」，
  而 `sort` 是**每个频道各自从 1 开始数**的。跨频道的两个金若 `sort` 恰好接近、
  `recordTime` 又落在同一秒，会被误判成同一发十连——不报错，只会凭空多出一组多金。
  所以是两个独立数组各跑一遍 `multiGoldGroups()`，不是先拍平再跑。
- **2 金用中文字「双金」，3 金及以上用阿拉伯数字**（`十连 3 金` / `十连 4 金`）。
  「双」是约定俗成的固定说法，读起来比「2 金」自然；三金、四金没有这种说法，写数字更好认，也省得去数汉字。
- 实测样本：`雅 79 抽 → 1 抽 → 5 抽` 是一发十连出**三金**（v1.4）；音擎也有 `啜泣摇篮 68 → 青溟笼舍 4 → 青溟笼舍 2` 的三金。
- 把三金写成「十连双金」是**事实错误**，不是措辞问题；总数也会错（5 组多金里含 1 组三金时，双金应是 ×4 而不是 ×5）。
- 实现：`multiGoldGroups()` 返回整组，按 `length` 分档落到 `nameTemplate` / `nameTemplate3` / `nameTemplate4`；
  指标侧同时给出 `multiGoldRounds`（总数）、`multiGold2` / `multiGold3` / `multiGold4`（分档计数）、`maxMultiGold`（最大金数）。
- 柱上的青点**大小随金数变化**（2 金 6px、3 金 8px、4 金 10px）——同尺寸会让「两次双金」和「一次三金」长得一模一样。

- **每个连段长度都要出标签，不能只留最长的。** 账号里同时存在 5 连歪和 3 连歪时，两条都要显示——
  只取最长会让「3 连歪」这个事实在报表里消失。
- **连段标签从 `minK: 3` 起**：`2 连 UP` / `2 连歪` 太常见，没有信息量，只留 3 连及以上。

### 5.1 标签冲突与优先级

标签会撞车，必须去重，否则同一件事说两遍或自相矛盾：

| 冲突 | 处理 |
|---|---|
| `运势极佳`（最长连 UP ≥ 4） vs `代理人 K 连 UP` | 同一件事。有具体连段标签时**丢掉概括标签**（配置 `suppressWhen`） |
| `时运不济`（最长连歪 ≥ 3） vs `代理人 K 连歪` | 同上 |
| `欧气附体` vs `非酋附体` | 互斥。同时成立时**保留负向**（更值得注意），丢掉正向 |

实现：配置数组里**靠前的优先级更高**；`suppressWhen: [id...]` 声明「这些标签存在时我就不出现」。
被丢掉的标签会在构建日志里打印，便于核对。
- **连段提示的格式**：`v1.0～1.1：朱鸢（格莉丝） → 青衣（猫又） → 简（「11号」）`
  - 版本写区间：同版本 `v2.0`，连续区间 `v1.0～1.1`（**尾版本要写全**，`v2.1～2.3` 不能缩成 `v2.1～3`，会被读成「到 v3」）
  - 每一环带出歪出/副金的角色名，写在括号里；直出就只写名字
- **标签直接换行，不裁剪也不折叠。** 标签本身就是结论，藏进 `+N` 等于让用户多点一次才看得到。
  标签行用 `flex-wrap: wrap`；图表区是 flex 撑满的，会让出高度（标签从 1 行变 2 行时图表约少 30px，仍装得下首屏）。
- **光标统一 `pointer`。** 大标题、标签、详情行——凡是能悬浮出提示的都用手形，不要混用 `default` / `help`。
- **只有出现不止一次才写 `×N`**：单次就是 `似非实欧`、`十连双金`，不要写成 `×1`。单次出现时也不加计数后缀。
- **提示文案用玩家话，不要用图表内部术语。** 「极欧柱 N 根」这种说法读者看不懂；要写成
  「十连出过 N 次双金 · N 次在 40 抽内出金」。任何 `柱 / 段 / 轴` 这类词都不该出现在面向读者的句子里。
- 计数类标签 hover 显示具体轮次（版本 + 角色链），用自绘深色气泡（`data-tip` + JS 定位），**不要用原生 `title`**。
- 联动高亮：标签用 `data-bars` 记录索引区间（`12-15;18-21`），hover 时 `highlight` 对应柱 + 灰色 `markArea` 区间带，离开时 `downplay` 并清空。
  **十连多金标签走另一条通道 `data-gold-sorts`**，原因见下方「多金标签的索引不能复用 `data-bars`」。

## 6. 第二屏：抽卡详情

- 面板头：`抽卡详情`（15px/700）+ 6 个频段标签（独家 / 音擎 / 常驻 / 邦布 / 复刻角色 / 复刻音擎），激活标签金色 + 2px 下划线；右侧「显示真实抽数」勾选 + meta。
- **数据覆盖全部 6 个频段**，默认示例：独家 41 / 音擎 11 / 常驻 9 / 邦布 34 / 复刻角色 1 / 复刻音擎 0，合计 96 金。
- 每行：**26px 方形圆角图标**（源图 96px，居中裁切）+ 横向条 + 紧贴条右侧（6px）的「歪」红章（无章时占同宽透明位，**不要甩到行尾**）。
- 横条：宽度 = 抽数 / 100 的**轨道占比**（78 抽 ≈ 78%），最小 44px；只用地两色——绿 `#2E8F45` = ≤ 该频段每金均值，红 `#FF5F6D` + 13% 黑斜纹 = > 均值；条内写 `N抽`。
- 歪章只出现在有 50/50 的频段（独家 / 音擎 / 复刻角色 / 复刻音擎）的非 UP 金；常驻、邦布不出现。
- **显示真实抽数**（默认不勾，始终与标签同一行、右对齐）：勾上后按时间正序把歪的抽数并进下一个 UP，只留 UP 行；十连副金并回**同一轮**；meta 改为 `N 次 UP · 每 UP X 抽`；常驻/邦布禁用该勾选。
- 列表按时间**从新到旧**；**详情区固定高度 480px + 内部滚动**（`overscroll-behavior: contain`）；
  空频段显示「这个频段还没有 S 级记录」，并在剩余空间里垂直居中。
  - **为什么不用自适应高度**：各频道行数差异极大（独家 41 行、复刻音擎 0 行）。
    随内容自适应会让页面高度剧烈变化，滚动条被浏览器收回，详情卡在视口里跳动几百像素。
  - **为什么不用「按最大频道锁定高度」**：空频道会留下一大片空白，卡片被撑到 1300px 以上。
  - 固定高度 + 内部滚动是唯一同时满足「切频道不跳」与「不过高」的做法。
  - **不要给 `#detail-list` 加 `display: flex`**：内部 `.detail-group` 已经是 flex 布局，
    外层再改 flex 会把图标和抽数轨道挤变形。
- **面板右上角只写 `N 金 · 每金 X 抽`**（合并模式写 `N 次 UP · 每 UP X 抽`），**不要**再追加「从新到旧」之类的排序说明——排序是固定行为，不必写出来占位置。
- 版本括号：相邻同 `version` 的行归为一组，组左侧 1px 方括号，**括号右侧写版本号**（9.5px mono 灰字），组间留 5px。
- 行悬浮 tip：逐金写 `名字 / vX · 出金时间 / 距上一金 N 抽 · UP|歪`；合并写 `本轮 N 抽 ＝ UP a + 歪 b` 与 `歪出：名字 b 抽`，无歪写 `本轮 N 抽 · 无歪`；常驻、邦布不标 UP/歪。
  - **「歪出」要读 `losts`（真正歪掉的角色），不是 `side`。** `side` 只装十连副金，用错会让每一行都显示 `歪出：—`。
  - 本轮既无歪又有十连副金时，写 `本轮 N 抽 · 无歪 · 十连副金 〇〇`。
  - 名字本身已带 `「」` 的（如「11号」）**不要再套一层**，否则会写出 `「「11号」」`。
- 图标全部本地化：`assets/items/<item_id>.png`（96px），失败回退 `assets/items/_fallback.png`，**不裂图、不引 CDN**。

## 9. 实现要点（ECharts 与踩坑记录）

这一节是**实现模板时踩出来的经验**，不是可选项——重写实现时照做，能省掉大量返工。

### 9.1 ECharts 用法

- **用 SVG renderer**，不是 canvas：报表要干净缩放、导出图片更清晰。
- **头像**：`scatter` + `symbol: 'image://assets/avatars/<id>.png'`，x 用 **0 基索引** `[i, y]`，
  `symbolOffset` 做垂直错位——每多一层头像往下挪一个 `ICON_STEP`。
- **柱顶写总抽数**：`scatter` + `symbolSize: 1` + 透明 `itemStyle`，只留 `label`。
  偏移量必须按该柱的头像层数**逐条算**，写死一个 `distance` 会被头像盖住。
- **柱内段内写字**：同一个 `scatter` 思路，或用 series 的 `label.position: 'inside'`。
- **已废弃的写法**：双 x 轴、`markLine` 画百分比上限。**不要加回来**。
- **标签联动高亮**：`dispatchAction({type:'highlight'})` + 临时 `markArea`（半透明灰）做区间带，
  `mouseleave` 时 `downplay` 并清空 `markArea`；柱体 `emphasis` 用白描边保证看得见。

#### 多金标签的索引不能复用 `data-bars`

「十连双金 / 十连 3 金」也要能悬浮高亮对应柱，但它**不能**像连 UP / 连歪那样存 round 下标：

- `multiGold` 是**角色池 + 音擎合并**统计的（见 `multiGoldGoldsByChannel`），
  而主图一次只画一个频道，两边的 round 编号是**两套互不相干的编号**。
  把音擎那几组的 round 下标当角色池下标用，会高亮到完全无关的柱子上——而且不报错。
- 所以构建时只带**频道内 `sort` 序号**（`multiGoldSorts`），前端按当前频道现算柱位。
  当前频道里没有的那些 `findIndex` 返回 `-1`，自动跳过，切 tab 也不会错标。

前端换算必须与**多金青点共用同一份** `barSortOf(sort)`：

```js
const barSortOf = (sort) => all.findIndex(
  (r) => r.sort === sort || r.side.some((s) => s.sort === sort),
);
```

`r.side` 那半句不能省：多金组的最后一金可能是「十连副金」，它不属于任何 round 的 `sort`，
只记录在某一轮的 `side[]` 里。少了这半句，副金落组的那些就找不到柱子。

两处（青点位置、标签高亮）各写一份映射，迟早会漂成「青点在 A 柱、高亮圈住 B 柱」，而两边都不报错。
**所以映射只有 `barSortOf` 一个入口。**

实测（joker 71 柱）：

| 悬浮标签 | 独家频道命中 | 音擎频道命中 |
|---|---|---|
| `十连双金 ×5` | 6 根（4 组，柱位 8 / 9 / 46 / 47 / 50 / 59） | 1 根（1 组，另一金是副金） |
| `十连 3 金 ×2` | **3 根**（柱位 24 / 25 / 26，雅 79 → 1 → 5） | 2 根（柱位 13 / 14，另一金是副金） |

命中根数**少于组内金数**是正常的：同一发十连里排在 UP 之后的**副金**没有独立柱子，
它记录在某一轮的 `side[]` 里，只会随那一轮一起亮。所以「3 金组只亮 2 根」不代表漏画。

**一组多金的全部金都要亮，不能只亮最后一根。** 早先 `multiGoldSorts` 每组只存
`g[g.length - 1].sort`，于是一组三金只高亮 1 根柱子——标签写着「十连 3 金」，
图上只有一根亮，读起来像只出了 1 金。现在每组把**全部金的 sort** 都带上，
组与组之间用 `null` 占位分隔（展开成一维数组），前端逐组解析、逐根点亮。

`null` 分隔不能省：一组三金的三根柱必须一起亮，而两组双金不能因为挨着就串成一串。
前端遇到空段就知道「上一组结束」。

**音擎那组三金只有 2 根可亮**，因为第三金是同一发十连的副金，没有独立柱子
（它记录在某一轮的 `side[]` 里）。这是数据形状决定的，不是漏画。

天猪的两组双金都在角色池（柱位 21 / 26），切到音擎/复刻后命中 0 根——**不画高亮是正确的**，
不要为了「看起来有反应」而在没命中的频道里乱圈。

### 9.2 图标缓存

- 报表里不出现任何外链：`assets/items/<item_id>.png`（96px 方形）与 `assets/avatars/<role_id>.png`（96px 圆形）。
- 生成顺序：**先查缓存**，命中直接复制；缺的才下载，居中裁切 96px 后写回缓存，下次复用。
- 下载失败用 `assets/items/_fallback.png` 顶上，详情图标另加 `onerror` 回退。**不允许裂图，也不允许退回官方 CDN。**
- 本机 Python `urllib` 直连 CDN 常报 `CERTIFICATE_VERIFY_FAILED`，改用 `curl --retry 2`；
  darkmatter 单张约 7 秒，批量下载用 4–6 并发。

### 9.3 验收方法

```bash
node scripts/build-report.mjs --data data/<账号>   # 先出报表
node scripts/screenshot.mjs                        # 两档尺寸一次出齐 → docs/shots/
node scripts/screenshot.mjs --privacy 2            # 对外用的图：先点全打码
node scripts/screenshot.mjs --chart 音擎            # 截频段 tab 切过去之后的状态
node scripts/screenshot.mjs --filter 2             # 截版本过滤生效后的状态（多个写 --filter 1,2）
node scripts/screenshot.mjs --html p.html --out-dir /tmp/x   # 指定产物与输出位置
```

- 脚本默认出 `1440x900` 与 `1280x800` 两张，核对**首屏无滚动、图例单行**。它复用 `drivers.mjs` 的 `findChrome()`，
  `--user-data-dir` 已焊死（不带的 Chrome headless 会去抢默认 profile 直接失败），**不需要 Playwright，也不联网**。
- **不要**按 `SKILL.md` §0 的浏览器优先级现拼 Chrome 命令行：那是**采集期**找「能扫码登录的浏览器」的语义，
  跟「截一张本地 HTML 的图」是两件事。
- tooltip 用**临时副本**注入 `dispatchAction({type:'showTip'})` 后截图，用完删除，别留在产物里。
- 图片必须先确认真的加载了（`naturalWidth > 0`），不能只看 DOM 里有 `<img>`：
  截图环境若没开图片加载，头像会是空白，容易误判成「画出来了」。
- 交互（频段 tab / 版本过滤）用 `--chart` / `--filter` 截，不要手拼脚本；改动后也要手动点一遍确认。
  截交互后的状态要等 `init()` 跑完再点，否则拿到的是未初始化的空图。

**两个坐标轴必须固定：构建时自动断言，不达标会让构建失败。**

```bash
node scripts/build-report.mjs --data data/tianzhu   # 坐标轴退化 → 退出码 1
```

校验分两级：

| 级别 | 行为 | 包含 |
|---|---|---|
| `fatal` | 打印 `✖`、**不写出产物、退出码 1** | 坐标轴退化：`charts.js` 没真正读 `CFG.numbers.axisWinRateMax` / `axisPullsMax`、配置缺失、某频道峰值超过固定上限 |
| `warn` | 打印 `⚠️`、照常出图、退出码 0 | 数据可疑点：缺图标（有占位图兜底，是设计好的降级）、金数/抽数口径对不上 |

坐标轴检查项：
- `config.numbers.axisWinRateMax` / `axisPullsMax` 是否配齐；
- **`charts.js` 里是否真的读了这个两个配置键**（先剥掉注释再匹配，否则会被解释这段历史的注释骗过去）；
- 每个可画频道的「不歪率峰值」是否超过右轴固定上限、「最高柱」是否超过左轴固定上限。

**为什么必须退出 1 而不是只打告警**：这条断言的整个存在意义是「不靠人记得」。
只 `console.warn` 然后 `process.exit(0)`，随手跑一次就漏过去了，下次照样静默退回自适应。
同理，**`writeFileSync` 必须在校验之后**——早先写在前头，就算退出 1，坏产物也已经躺在
`output/` 里了：CI 红了，但人打开文件看到的还是坏图。

验证方式（改这段代码后照做一次）：
1. 把 `charts.js` 里 `const winMax = CFG.numbers.axisWinRateMax` 临时改成 `(null)`（**注释保留**）；
2. 跑构建 → 必须退出码 1、打印「没有真正读取」、且**目标文件没有被写出**；
3. 改回来 → 退出码 0。

为什么要有这条：**右轴曾经「修好又退回去」一次**——左轴改成了「先读配置」，
右轴漏了同一步、只留了自适应，于是角色池显 60%、音擎显 80%，跨图没法对比。
之所以没被发现，是因为**复刻角色那栏峰值恰好 100%、自适应出来也是 100%**，随便点开一个频道看着是对的。
**验坐标轴必须六个频道全验，不能只看一张图**：

| 频道 | 不歪率峰值 | 右轴应显示 |
|---|---|---|
| 天猪 独家 | 50% | 100% |
| 天猪 音擎 | 66.7% | 100% |
| 天猪 复刻角色 | 100% | 100%（这张恰好看不出问题） |
| joker 独家 | 56.3% | 100% |
| joker 音擎 | 100% | 100% |

**往产物里注入脚本时，只能插在最后一个 `</body>` 之前。**
报表把 ECharts 源码内联进了 HTML，那段源码的字符串里本身就含 `</body>`
（实测产物有 2 个匹配，第一个落在 echarts 内部）。用 `String.replace('</body>', …)`
会命中第一个，等于把注入脚本塞进 echarts 源码中间——表现为**图表整块变白**，
而且报错信息完全没有指向真正的原因。`scripts/screenshot.mjs` 的 `withPrivacy()`
就是用 `lastIndexOf('</body>')` 修的这个问题。

## 10. 改动边界

- 改**称号 / 标签阈值 / 配色 / 文案 / 频道定义** → 只改 `config/report.json`。
- 改**计算口径** → 改 `scripts/build-report.mjs`，并同步本文件 §1。
- 改**视觉** → 改 `assets/report/charts.css` / `charts.js`，并同步本文件 §2–§6。
- 改**配色 / 文案** → 只改 `config/report.json`：颜色经 `--accent` / `--detail-good` / `--detail-bad` / `--loss-stamp`
  注入 CSS 变量，`copy.chartTitle / detailTitle / mergeToggle` 在构建时替换模板占位符。
  **不要在 CSS 里另写一份色值**——那样改配置就不生效了（这是过去的实际 bug）。
- 新增角色/音擎/邦布 → 先跑 `node scripts/sync-icons.mjs` 补图（会自动重跑 64px 压缩），再构建。
- 任何改动后都要跑 §8 的自检与 §9.3 的验收，确认控制台数字与截图。
