# 抽卡报表规则（规范）

这个文件是**报表口径与呈现的规范**，回答两个问题：**为什么这样算**、**为什么这样画**。
它不随实现变化——代码可以重写、模板可以替换，这里定义的规则是要长期守住的。

## 谁该读这个文件

| 读者 | 用法 |
|---|---|
| **用户 / Agent 日常出报表** | **不用读这个文件**。直接 `node scripts/build-report.mjs`，模板已经实现全部规则 |
| **开发 / 修改这个 skill** | **必须读**。改口径、改配色、改版式前先看这里，改完回来同步 |
| **接手维护的人** | 先读这里，再看 `scripts/build-report.mjs` 与 `assets/report/` 的实现 |

**规则与实现的分工：**

| 层 | 位置 | 角色 |
|---|---|---|
| 规则（本文件） | `references/report-rules.md` | 规范。定义口径、配色语义、版式要求、踩过的坑 |
| 配置 | `config/report.json` | 可调参数：称号分档、标签阈值、配色值、文案、频道定义 |
| 实现 | `scripts/build-report.mjs` + `assets/report/` | 默认模板。把规则落成可运行代码 |

**优先用模板，不要重新发明**：`scripts/build-report.mjs` 已经实现了下面的全部规则。
只有在模板确实不适用、或你要做定制版式时，才需要按本文件手写实现。

## 0. 怎么出报表

```bash
node scripts/build-report.mjs          # data/ → output/report.html
```

产物：单文件 `output/report.html`，内联数据、ECharts 与用到的图标（base64），可单独发送。
ECharts 5.6.0 已 vendored 在 `assets/vendor/echarts.min.js`（校验见 §7），报表不联网、不用 CDN。

## 1. 口径

- **UP 轮**：从上一个 UP 结束后开始。`off` = 期间所有非 UP 金的抽数，`up` = UP 金自己的抽数，`total = off + up`。
- **十连副金并回本轮**：同一发十连里排在 UP **之后**的非 UP 金（`record_time` 同秒且 `sort` 差 ≤ 9），把它的 `count` 并入这一轮的总抽，本轮仍算**直出**。不留给下一个 UP——否则下一位会被误判成「先歪」。
- **保底获得（guar）**：上一轮末尾带出了十连副金，说明 50/50 已经歪过，这一发是大保底。它**不计入 50/50 胜场**，并且**打断连 UP**。
- **指标**（每金 / 每 UP 一律用「官方总抽 − 当前垫抽」）：
  - 每 UP 均 = (角色池总抽 − 角色池垫抽) / UP 轮数
  - 不歪率 = 胜场 / UP 轮数（胜场 = 直出且非保底获得）
  - 平均每金 = (该频道总抽 − 该频道垫抽) / S 数
  - **为什么扣垫抽**：`type_stats[].total_count` 含「已经抽掉、但还没出 S」的垫抽。
    把它摊进每个金，等于把一个尚未结算的成本算进历史均值。官方自己的 `avr_up_count`
    就是扣掉垫抽的：常驻 650/9 = 72.2，官方 65.8 = (650−58)/9；复刻角色 90/1 = 90，官方 76 = (90−14)/1。
    示例账号的角色池垫抽恰好是 0，所以旧口径没露馅——换个号就会系统性偏非，**称号也会跟着偏**。
  - 报表构建时会拿扣垫抽后的每金和官方 `avr_up_count` 交叉核对，差超 0.1 就告警。
- **欧判定**：`total ≤ 该账号的每 UP 均` 即算欧（歪了但更省也算）。**不要写死 87.9**，那是示例账号的值。
- **极欧**：`total ≤ 40`（`config.report.json` 的 `numbers.extremePulls`）。

### 1.1 完整性校验

```
sum(cur_records[].count) + type_stats[].next_s_cur_times == type_stats[].total_count
```

6/6 频道实测成立。它校验的是**抽数**，比「金数对得上」更强。
另：`index.total_gacha_count` 与 `total_s_count` **都不含邦布**（实测 3714 / 62，六频道相加 5375 / 96）。
**邦布抽卡用的是邦布币，和调频券不是同一种货币**，所以跨频道的「总抽卡数 / 平均每金 / S 级总数」一律扣掉邦布，只统计同一货币的频道（`config.report.json` 里 `channels[].countsTowardTotals`）。邦布自己的每金成本在 KPI「每邦布」里单独给。

## 2. 首屏

- **标题行**：`昵称 · UID 胶囊 · 大标题 · 隐私开关（眼睛）`，右侧留白处放 **GitHub 仓库链接**，一行不换行。
  - **显示的是安装命令 `npx skills add atian25/zzz-stats`，不是裸 URL**，点击仍打开仓库。
    看到报表的人最可能想做的是装上它，一条能直接粘的命令比还要再翻 README 的地址有用。
    地址与文案在 `config/report.json` 的 `copy.repo`。
  - 文字前带 **GitHub 图标**（内联 SVG，`currentColor` 描边，13px），整行用 `inline-flex` 垂直居中。
  - 样式要低调：等宽小字、灰色，hover 时图标与文字一起变主题金色；`target="_blank" rel="noopener"`。
  - 只替换文字节点、保留图标（`#repo-text`），不要用 `textContent` 整段覆盖，否则 SVG 会被清掉。
  顺序是「先是谁，再是账号标识，最后是评价」——称号放最后，因为它是对这个人的结论，不是身份信息。
- **大标题**：按每 UP 均查 `config.report.json` 的 `titles.tiers`（10 档，见 §4）。**按公式算出再写**，不要写死。
- **次行四项**：`N 抽 总抽卡数 / N S 级代理人 / N UP 代理人 / N UP 音擎`，
  行尾灰色等宽小字 `国服 · 采集 YYYY-MM-DD HH:MM`。
  - **不要放版本区间**：版本在横轴上已经按柱标注了，行尾再写一遍是冗余。
  - **不要放 region**（`prod_gf_cn` 这类）：对读者没有意义，排查问题时看 `data/meta.json`。
  - **时间必须带年份**：跨年看报表时 `MM-DD` 会有歧义。
  - **前两项 = 全账号汇总**，口径是「除邦布外全部五个频道」，
    实测 `2372(UP) + 650(常驻) + 590(音擎) + 90(独家重映) + 12(音擎回响) = 3714`，
    与官方 `total_gacha_count` / `total_s_count` 完全一致（3714 / 62）。
  - **后两项 = UP 数**，取自官方 `type_stats[].up_count`（实测代理人 27、音擎 8）。
    **UP 写「UP 代理人 / UP 音擎」即可，不要再加「S 级」**——UP 角色的稀有度恒为 S，写了是废话。
  - **注意 41 ≠ 27**：41 是「独家」频道的全部 S（27 UP + 13 歪出 + 1 副金），62 是全账号全部 S。
    不要把 41 当 UP 数。
  - **用「代理人」而不是「角色」**：游戏内角色池抽出来的就是代理人，术语要跟游戏一致。
  - **不放「UP 池抽卡数」**：该数字在下方 KPI「每 UP 角色」的语境里已经隐含，首屏不必再占一格。
  - **界面上不要堆括注**（`不含邦布` / `含歪出` 之类）：口径写在本文件里，界面只给干净的四项。
  - **不要写「平均每金」这种跨频道混算值**：`3714 ÷ 62 = 59.9` 把不同频道的抽数合在一起除以总金数，
    等于假定它们在同一个计价体系，实际期望完全不同。各频道真实成本看下面的 KPI。
- **KPI 固定 5 格一行**（窄屏也不折行）：`角色池不歪 / 每 UP 角色 / 每 UP 音擎 / 常驻每金 / 每邦布`。
  这 5 个数全部按「扣垫抽」口径算（见 §1），不要退回含垫抽的总抽 ÷ 金数。
- **隐私开关**：称号右侧的眼睛按钮（UID 胶囊只负责显示），**三态循环**（默认全显示）：① 全显示 → ② 仅打码 UID（`UID 116***92`）→ ③ 全打码（昵称只留首字 + UID 打码）→ 回到 ①。图标用内联 SVG 三态。
  **对外截图必须先点到全打码（从默认点 2 下）。**
  - **这条不是提醒，是硬约束。** 已经踩过一次：README 的预览图连着两版把真名和 UID
    截进了公开仓库，事后才发现。截图脚本里必须先
    `eye.click(); eye.click();`，再断言 `#eye` 的 `data-state === '2'` 与
    `#nick` 含 `*`，断言不过就**中止截图**——宁可没有图，也不要一张带真名的图。
  - 打码版一旦提交、推送就收不回来了：`git show <旧commit>:docs/preview.png` 永远取得到。
    所以这一步只能在截图前做对，事后补救是补不回来的。
- `document.title` 也要跟着三态变，否则标签页会泄露昵称、或与页面状态不一致。
- **验证隐私开关时不要用已打码的昵称做数据**：`maskName('天*')` 仍返回 `天*`，
  看起来像「点了没反应」。测试数据里要放完整昵称，才能验证状态 2 真的把名字盖掉。

## 3. 主图（`抽卡总览`）

### 3.0 配色语义（值在 `config.report.json` → `colors`）

颜色不是装饰，每一个都对应一个判定，换色等于换语义：

| 含义 | 色值 |
|---|---|
| 极欧 ≤ 40 抽（本发上段） | 蓝 `#3F7BFF` |
| 极欧周期的歪段 | 深蓝 `#1B3C78` |
| 欧 > 40 抽（本发上段） | 深绿 `#2E8F45` |
| 欧周期的歪段 | 深绿 `#1B5E2A` |
| 非酋本发上段（超均值） | 亮红 `#FF5F6D` |
| 非酋歪段 | 深红 `#A81E28` |
| 累计不歪率折线 | 金 `#F2E23C` |
| 十连多金圆点 | 青 `#7BE0FF` |
| 版本分隔虚线 | 灰 `#3A3A42` |

**堆叠柱的读法**：下段 = 歪掉的抽数，上段 = UP 本身。**柱体颜色表达运气（欧/非），不表达 50/50 输赢**——
「歪」只在第二屏用红章标出。这两件事不要混在一根柱子上表达。

### 3.1 版式

- 面板标题 `抽卡总览`（15px/700），右侧灰字 `N 个 UP · N 抽`。
- **堆叠柱**：下段 = `off`（歪掉的抽数），上段 = `up`（含十连副金）。**柱顶**写本轮总成本；**柱内**各段写各自抽数（段 < 8 抽不写）。
- **柱顶头像栈**：每根柱顶上摞该轮涉及的所有金（**头像 22px，层间距 23px**），**先出的在上、后出的在下**。叠放顺序是「歪出角色 → UP → 十连副金」：歪出的先出，所以在最上层；十连副金在 UP 之后出，所以在最下层。
  **歪出的角色必须画出来**——只画 UP 会让「这一轮歪了谁」在图上消失。实测 27 根 UP 柱里有 13 根带歪出头像，加上 1 个十连副金，柱顶头像总数 = 41 = 全部金数。
- **柱顶总抽数**：写在该柱头像栈的**正上方**，不能被头像压住；头像层数不同，所以每根柱的偏移量要按自己的层数算。
- **红柱 ≠ 歪**：红是「超出该账号每 UP 均」（非酋），绿/蓝是欧。真正的 50/50 结果看「歪」章（在详情里）。
- **累计不歪率**：金色折线，右轴按数据自适应（峰值向上取整到 10 的倍数 + 10% 余量，上限 100）。
  **不要写死 60%**：比示例账号更欧的曲线会顶到框外被截断，而 50% 的号看不出这个问题。
- **右轴下限要留一点负余量（默认 `-4%`）。** 开局的累计不歪率是 0%（还没赢过），
  这一段会正好画在 grid 底边上、和灰色 x 轴基线重合，1.4px 的描边再被裁掉一半。
  负刻度本身**不显示**（formatter 过滤 `v < 0`），它只负责把 0% 那条线抬离底边。
- **折线的 `z` 必须高于柱子的 `z`（柱子默认 2，折线设 3）。**
  两者同级时折线会被柱体压住，曲线一进到柱子范围内就看不见——
  表现为「曲线从中间才开始，前面那几根柱子没有线」。
  用户会以为数据缺失，实际是图层顺序问题。3 高于柱子、低于头像（4）与双金点（5），
  既能整段可见，又不会骑到角色脸上。
  - 两个问题要分清：**z 太低**＝线被柱子挡住（整段消失）；
    **0% 贴底**＝线在柱子外面也看不见（只影响 0% 那几段）。两个都要修。
- **不画版本分隔竖线。** 早先版本用贯穿全图的灰色虚线标版本切换，但柱顶头像是摞在柱子上方的，
  竖线一定会插进头像和总抽数里，噪音大于信息。横轴本身按版本标注（`v1.0` / `v1.1`），分界已经看得出来。
- 横坐标写 `v1.0`、`v2.7`（**带 v**）——同一版本多根柱时靠分隔线区分，不要加池序号。
- **图例控制在 5–6 条，单行**，只留「光看图看不出来」的语义：红＝超出均值 · 深色段＝歪掉的抽数 · 蓝＝极欧 ≤ 40 抽 · 绿＝欧 · 黄线＝累计不歪率 · 青点＝十连双金 ×N，行尾灰字「官方接口 · N 条 S 记录」。
  **不要**把「柱顶＝总成本」「柱内＝各段抽数」「头像先出的在上」这类自解释的东西也写成图例——那会把注脚变成说明书。
- **首屏无滚动**：1440×900 与 1280×800 都要首屏装下、图例单行；详情在第二屏，首屏底部不露出详情边线。
- **两张卡必须等宽、左右边界对齐**。主图在 `.screen` 内（该容器自带左右 20px 内边距），
  详情卡在 `.screen` 之外，**必须补同样的水平外边距**（`margin: 0 20px`），否则详情会顶到视口两边。
- **详情行悬浮高亮的是这一行自己**，不是联动上方主图。
  - 用 `:hover` 给整行加淡背景（`rgba(240,240,241,.07)`），左右各外扩 6px，
    让高亮像一条整宽的横带，而不是只包住图标和条（后者看起来像「选中了图标」）。
  - 同时把条轻微提亮（`filter: brightness(1.12)`），行背景和条一起强调。
  - 纯 CSS 即可，不要写 JS 去操作 ECharts —— 详情行和柱子数量本来就不一一对应
    （逐金 41 行 vs 主图 27 柱），跨面板联动只会误导。
- **主图可折叠，默认展开。** 折叠是为截图服务的：把主图收起来后 `.screen` 不再撑满 100vh，
  详情顶上来，顶部信息 + 详情能进同一屏（实测 1440×900 下一屏可见 20 行详情）。
  - 折叠**只收外层容器高度**（`.chart-main { height:0; overflow:hidden }`），
    **绝不对 `#chart` 用 `display:none`**——那会让 ECharts 读到 0 尺寸，展开后画布塌掉。
  - 展开时**不要重建图表**，只需 `chart.resize()`。`#chart` 的 display 始终是 block，
    容器尺寸恢复后 resize 即可还原，实测 `instH` 全程不变。
  - 按钮放在面板头右侧（`.panel-meta` 之后），箭头 0° ↔ 180° 旋转，文案「收起 / 展开」。
- **面板标题要垂直居中**：`.panel-head` 用 `align-items: center`，不要用 `baseline`——
  标题（15px 粗体）与右侧灰字（11px 等宽）基线不同，用 baseline 会让标题视觉偏下约 5px。

### 3.2 tooltip（axis trigger）

formatter 返回的是**纯文本多行**，必须显式保留换行：`extraCssText: 'white-space: pre'`
（ECharts 默认会把 `\n` 折叠成空格，表现为「换行没了」）。

```
猫又 → 南宫羽                  ← 歪出/副金在前，UP 在后；无歪时只写 UP 名
卡池 v2.7 · 2025-03-15 21:34   ← 版本后接该 UP 出金时间（record_time 转本地时区）
总共 44 抽，直出                ← 未歪
总共 52 抽，大保底，上个池子歪了「猫又」   ← 保底获得（guar）
总共 108 抽，大保底，37 抽歪「11号」      ← 歪了
本发十连双金                    ← 仅该发是双金
似非实欧，白赚大保底             ← 十连副金且本轮直出
累计不歪率 50%                  ← 永远最后一行
```


### 3.3 垫抽（保底进度）

垫抽 = 「离下一个 S 还垫了多少抽」，来自官方 `type_stats[].next_s_cur_times`。数据一直在落盘，
但过去 0 处展示——而这恰恰是玩家最想看的数。

- **只在第二屏「抽卡详情」里出现，作为正文的一行**，造型照官方调频页：
  **左边金色问号方块**（下一个 S 未知）+ **右边绿色斜纹条**，条内写 `已垫 N 抽`。
  **条右侧不要写 `/90`**：保底上限属于悬浮才需要的细节，常驻显示会把一行变成三个数字，
  反而看不清主次。上限只在 tip 里出现。
- **主图（抽卡总览）不放垫抽。** 主图讲的是「历史每一轮的成本」，垫抽是「当前这一档的状态」，
  两种时间视角混在一个面板头里会让人以为柱子也算进了垫抽。
- **不要放在面板头上**。详情头的横向空间要挤 6 个频段 tab + 勾选框 + meta，
  再塞一条进度条，两边都看不清；而且垫抽和下面的金条是同一套「长度＝数值」的读法，放正文才连贯。
- **放在最新版本组内部的第一行**，不是列表外面。外面那层没有版本括号的缩进
  （1px 括号 + 7px gap + 版本号宽度 ≈ 42px），放外面问号块会比下面的头像整体左移 42px，一眼看出没对齐。
- **上边距要比普通行大（8px）**：这一行紧贴 tab 下划线，26px 的问号方块会被那条金色下划线视觉压住。
- **不要给这一行加分隔线**（`border-bottom` / `<hr>`）。它就在 tab 下划线正下方，
  再加一条横线会被读成「当前频段的第二个下划线」，而且横线铺满整行、比 tab 下划线长得多，像页面分割线。
  用 `margin` 留白分隔即可。
- **该频段进度为 0 时不画**（如独家 / 音擎：刚出完金或没垫）。显示一条空条只会让人以为坏了。
- **空频段也要画**（如音擎回响：垫了 12 抽、一金未出）。只写「这个频段还没有 S 级记录」
  等于把唯一有信息量的数藏起来。
- **保底上限在 `config/report.json` 的 `channels[].pityCap`**，按频段不同（见 `references/api.md` §5）：
  常驻 / 独家 / 独家重映 90，音擎 / 音擎回响 80，邦布 80。
  **不要用 `new_s_max_times`**：那是官方 UI 的区间展示值，不是硬保底
  （实测常驻该值 32，而该频道最长出金间隔是 80）。
- **剩 ≤ 10 抽时条变红**（`.pity-row[data-near="true"]`），表达「马上就要出了」。
- **悬浮显示「保底上限 + 上一个 S」**：行内只有「已垫 58 抽」，读者要知道还差多少、
  从谁开始垫的，都在 tip 里：`已垫 58 抽，还差 32 抽到保底（90 抽保底）` + `上一个 S：啜泣摇篮（v3.1）`。
  整条频道还没出过金时后半行不出现。
- **口径只在 `build-report.mjs` 算一次**：`{cur, cap, remain, pct, last}` 由构建产出，前端只负责画。

## 4. 称号（`config.report.json` → `titles.tiers`）

基准：角色池每 UP 期望 = 62.5 抽/金 × 1.5（50/50）= **93.75 抽**。

**大标题要能悬浮查看完整档位。** 鼠标移上去显示全部 10 档区间，**当前档加粗高亮**，第一行写清本账号的判定：

```
每 UP 均 87.9 抽 → 欧气满满大欧皇

≤ 62.5      终极无敌至尊欧皇
62.5 – 80   万里挑一至尊欧皇
80 – 90     欧气满满大欧皇      ← 这一行加粗 + 主题金色
90 – 95     欧非守恒
...
> 125       终极无敌至尊非酋

按「角色池每 UP 均（含歪）」判档
```

- 区间文案要**算出来**（`prev ~ maxPullsPerUp`），不要在提示里手写死。
- 当前档靠比对 `tiers[].name` 命中，不要按索引猜。
- **加粗 + 颜色表示命中的那一档**，不要用 `▶` 之类的符号前缀。
- 光标用 `pointer`（与 Tag、详情行一致，同是手形），**不要用 `cursor: help` 的问号光标**。
- 标题要给出可悬浮的**视觉暗示**，但**不要用虚线下划线**（像超链接，观感廉价）：
  hover 时用主题色柔光（`text-shadow` + `brightness`）即可。
- 气泡样式与图表内 tip 保持一致（同一个 `.tip` 组件）。
- 因为要加粗，这条提示走 `data-tip-html`（内容需转义后再拼 `<b>`）；其余提示仍走纯文本 `data-tip`，避免 XSS 面。

档位来自 2026-11 收集的 12 条工坊「抽卡总结」样本拟合，**不是人群百分位**；不歪率只是强相关，不能当判据。

| 每 UP 均 | 称号 |
|---|---|
| ≤ 62.5 | 终极无敌至尊欧皇 |
| ≤ 80 | 万里挑一至尊欧皇 |
| ≤ 90 | 欧气满满大欧皇 |
| ≤ 95 | 欧非守恒 |
| ≤ 99 | 欧气附体小欧皇 |

## 5. 标签（`config/report.json` → `tags.rules`）

规则是**数据驱动**的：每条 rule 有 `kind`（`metric` / `series` / `event` / `round`）、条件、配色和提示模板。条件不满足就不出现，不要为了好看硬凑。

| 标签 | 触发 |
|---|---|
| `欧气附体` | 十连双金 ≥ 1 次，或极欧柱 ≥ 2 根 |
| `运势极佳` | 最长连 UP ≥ 4 |
| `时运不济` | 最长连歪 ≥ 3（负向） |
| `非酋附体` | 每 UP 均 > 110（负向） |
| `代理人 K 连 UP ×N` | 连续直出段；**每个不同长度各出一个标签**，同一长度出现多次才加 ×N；**保底获得要打断连 UP** |
| `代理人 K 连歪 ×N` | 连续先歪段；同样是每个长度各出一个标签 |
| `十连双金 ×N` | 十连多金组数，**不写人名** |
| `似非实欧 ×N` | 先歪但总抽 < 该账号每 UP 均；蓝色 |

- **每个连段长度都要出标签，不能只留最长的。** 账号里同时存在 5 连歪和 3 连歪时，两条都要显示——
  只取最长会让「3 连歪」这个事实在报表里消失。
- **连段标签从 `minK: 3` 起**：`2 连 UP` / `2 连歪` 太常见，没有信息量，只留 3 连及以上。

### 5.1 标签冲突与优先级

标签会撞车，必须去重，否则同一件事说两遍或自相矛盾：

| 冲突 | 处理 |
|---|---|
| `运势极佳`（最长连 UP ≥ 4） vs `代理人 K 连 UP` | 同一件事。有具体连段标签时**丢掉概括标签**（配置 `suppressWhen`） |
| `时运不济`（最长连歪 ≥ 3） vs `代理人 K 连歪` | 同上 |
| `欧气附体` vs `非酋附体` | 互斥。同时成立时**保留负向**（更值得注意），丢掉正向 |

实现：配置数组里**靠前的优先级更高**；`suppressWhen: [id...]` 声明「这些标签存在时我就不出现」。
被丢掉的标签会在构建日志里打印，便于核对。
- **连段提示的格式**：`v1.0～1.1：朱鸢（格莉丝） → 青衣（猫又） → 简（「11号」）`
  - 版本写区间：同版本 `v2.0`，连续区间 `v1.0～1.1`（**尾版本要写全**，`v2.1～2.3` 不能缩成 `v2.1～3`，会被读成「到 v3」）
  - 每一环带出歪出/副金的角色名，写在括号里；直出就只写名字
- **标签直接换行，不裁剪也不折叠。** 标签本身就是结论，藏进 `+N` 等于让用户多点一次才看得到。
  标签行用 `flex-wrap: wrap`；图表区是 flex 撑满的，会让出高度（标签从 1 行变 2 行时图表约少 30px，仍装得下首屏）。
- **光标统一 `pointer`。** 大标题、标签、详情行——凡是能悬浮出提示的都用手形，不要混用 `default` / `help`。
- **只有出现不止一次才写 `×N`**：单次就是 `似非实欧`、`十连双金`，不要写成 `×1`。单次出现时也不加计数后缀。
- **提示文案用玩家话，不要用图表内部术语。** 「极欧柱 N 根」这种说法读者看不懂；要写成
  「十连出过 N 次双金 · N 次在 40 抽内出金」。任何 `柱 / 段 / 轴` 这类词都不该出现在面向读者的句子里。
- 计数类标签 hover 显示具体轮次（版本 + 角色链），用自绘深色气泡（`data-tip` + JS 定位），**不要用原生 `title`**。
- 联动高亮：标签用 `data-bars` 记录索引区间（`12-15;18-21`），hover 时 `highlight` 对应柱 + 灰色 `markArea` 区间带，离开时 `downplay` 并清空。

## 6. 第二屏：抽卡详情

- 面板头：`抽卡详情`（15px/700）+ 6 个频段标签（独家 / 音擎 / 常驻 / 邦布 / 复刻角色 / 复刻音擎），激活标签金色 + 2px 下划线；右侧「显示真实抽数」勾选 + meta。
- **数据覆盖全部 6 个频段**，默认示例：独家 41 / 音擎 11 / 常驻 9 / 邦布 34 / 复刻角色 1 / 复刻音擎 0，合计 96 金。
- 每行：**26px 方形圆角图标**（源图 96px，居中裁切）+ 横向条 + 紧贴条右侧（6px）的「歪」红章（无章时占同宽透明位，**不要甩到行尾**）。
- 横条：宽度 = 抽数 / 100 的**轨道占比**（78 抽 ≈ 78%），最小 44px；只用地两色——绿 `#2E8F45` = ≤ 该频段每金均值，红 `#FF5F6D` + 13% 黑斜纹 = > 均值；条内写 `N抽`。
- 歪章只出现在有 50/50 的频段（独家 / 音擎 / 复刻角色 / 复刻音擎）的非 UP 金；常驻、邦布不出现。
- **显示真实抽数**（默认不勾，始终与标签同一行、右对齐）：勾上后按时间正序把歪的抽数并进下一个 UP，只留 UP 行；十连副金并回**同一轮**；meta 改为 `N 次 UP · 每 UP X 抽`；常驻/邦布禁用该勾选。
- 列表按时间**从新到旧**；**详情区固定高度 480px + 内部滚动**（`overscroll-behavior: contain`）；
  空频段显示「这个频段还没有 S 级记录」，并在剩余空间里垂直居中。
  - **为什么不用自适应高度**：各频道行数差异极大（独家 41 行、复刻音擎 0 行）。
    随内容自适应会让页面高度剧烈变化，滚动条被浏览器收回，详情卡在视口里跳动几百像素。
  - **为什么不用「按最大频道锁定高度」**：空频道会留下一大片空白，卡片被撑到 1300px 以上。
  - 固定高度 + 内部滚动是唯一同时满足「切频道不跳」与「不过高」的做法。
  - **不要给 `#detail-list` 加 `display: flex`**：内部 `.detail-group` 已经是 flex 布局，
    外层再改 flex 会把图标和抽数轨道挤变形。
- **面板右上角只写 `N 金 · 每金 X 抽`**（合并模式写 `N 次 UP · 每 UP X 抽`），**不要**再追加「从新到旧」之类的排序说明——排序是固定行为，不必写出来占位置。
- 版本括号：相邻同 `version` 的行归为一组，组左侧 1px 方括号，**括号右侧写版本号**（9.5px mono 灰字），组间留 5px。
- 行悬浮 tip：逐金写 `名字 / vX · 出金时间 / 距上一金 N 抽 · UP|歪`；合并写 `本轮 N 抽 ＝ UP a + 歪 b` 与 `歪出：名字 b 抽`，无歪写 `本轮 N 抽 · 无歪`；常驻、邦布不标 UP/歪。
  - **「歪出」要读 `losts`（真正歪掉的角色），不是 `side`。** `side` 只装十连副金，用错会让每一行都显示 `歪出：—`。
  - 本轮既无歪又有十连副金时，写 `本轮 N 抽 · 无歪 · 十连副金 〇〇`。
  - 名字本身已带 `「」` 的（如「11号」）**不要再套一层**，否则会写出 `「「11号」」`。
- 图标全部本地化：`assets/items/<item_id>.png`（96px），失败回退 `assets/items/_fallback.png`，**不裂图、不引 CDN**。

## 9. 实现要点（ECharts 与踩坑记录）

这一节是**实现模板时踩出来的经验**，不是可选项——重写实现时照做，能省掉大量返工。

### 9.1 ECharts 用法

- **用 SVG renderer**，不是 canvas：报表要干净缩放、导出图片更清晰。
- **头像**：`scatter` + `symbol: 'image://assets/avatars/<id>.png'`，x 用 **0 基索引** `[i, y]`，
  `symbolOffset` 做垂直错位——每多一层头像往下挪一个 `ICON_STEP`。
- **柱顶写总抽数**：`scatter` + `symbolSize: 1` + 透明 `itemStyle`，只留 `label`。
  偏移量必须按该柱的头像层数**逐条算**，写死一个 `distance` 会被头像盖住。
- **柱内段内写字**：同一个 `scatter` 思路，或用 series 的 `label.position: 'inside'`。
- **已废弃的写法**：双 x 轴、`markLine` 画百分比上限。**不要加回来**。
- **标签联动高亮**：`dispatchAction({type:'highlight'})` + 临时 `markArea`（半透明灰）做区间带，
  `mouseleave` 时 `downplay` 并清空 `markArea`；柱体 `emphasis` 用白描边保证看得见。

### 9.2 图标缓存

- 报表里不出现任何外链：`assets/items/<item_id>.png`（96px 方形）与 `assets/avatars/<role_id>.png`（96px 圆形）。
- 生成顺序：**先查缓存**，命中直接复制；缺的才下载，居中裁切 96px 后写回缓存，下次复用。
- 下载失败用 `assets/items/_fallback.png` 顶上，详情图标另加 `onerror` 回退。**不允许裂图，也不允许退回官方 CDN。**
- 本机 Python `urllib` 直连 CDN 常报 `CERTIFICATE_VERIFY_FAILED`，改用 `curl --retry 2`；
  darkmatter 单张约 7 秒，批量下载用 4–6 并发。

### 9.3 验收方法

- headless Chrome `--window-size=1440,900` 与 `--window-size=1280,800` 各截一张，核对**首屏无滚动、图例单行**。
- tooltip 用**临时副本**注入 `dispatchAction({type:'showTip'})` 后截图，用完删除，别留在产物里。
- 图片必须先确认真的加载了（`naturalWidth > 0`），不能只看 DOM 里有 `<img>`：
  截图环境若没开图片加载，头像会是空白，容易误判成「画出来了」。

## 10. 改动边界

- 改**称号 / 标签阈值 / 配色 / 文案 / 频道定义** → 只改 `config/report.json`。
- 改**计算口径** → 改 `scripts/build-report.mjs`，并同步本文件 §1。
- 改**视觉** → 改 `assets/report/charts.css` / `charts.js`，并同步本文件 §2–§6。
- 改**配色 / 文案** → 只改 `config/report.json`：颜色经 `--accent` / `--detail-good` / `--detail-bad` / `--loss-stamp`
  注入 CSS 变量，`copy.chartTitle / detailTitle / mergeToggle` 在构建时替换模板占位符。
  **不要在 CSS 里另写一份色值**——那样改配置就不生效了（这是过去的实际 bug）。
- 新增角色/音擎/邦布 → 先跑 `node scripts/sync-icons.mjs` 补图（会自动重跑 64px 压缩），再构建。
- 任何改动后都要跑 §8 的自检与 §9.3 的验收，确认控制台数字与截图。
